# 시계 다이얼 시간 선택 UI 설계

날짜: 2026-08-04
대상: `apps/web/src/components/DateTimePicker.tsx`

## 문제

거래 입력 모달의 시간 입력이 네이티브 `<input type="time">`이다. 브라우저가 그리는
오전/오후·시·분 3열 휠 드롭다운이 뜨는데, 각 열을 **위아래로 스크롤해서** 값을 맞춰야 한다.
이 스크롤 조작이 불편하다는 것이 개선의 출발점이다.

부수적으로 드롭다운이 캘린더 위를 덮어 맥락이 가려지고, 브라우저 기본 UI라 앱 디자인과 따로 논다.

## 해결 방향

네이티브 `<input type="time">`을 걷어내고 **탭으로 고르는 시계 다이얼**로 교체한다.

## 결정 사항

| 항목      | 결정                            | 근거                                                                               |
| --------- | ------------------------------- | ---------------------------------------------------------------------------------- |
| 조작 방식 | 숫자 **탭만**. 바늘 드래그 없음 | 5분 단위라 타겟이 커서 탭으로 충분. 포인터 이벤트 처리를 안 들임                   |
| 분 정밀도 | **5분 단위** (00, 05, … 55)     | 가계부에서 분 단위 정확도는 무의미. 다이얼이 12칸으로 떨어져 타겟이 커짐           |
| 시 다이얼 | **12칸 + 오전/오후 토글**       | 이중 링(13~24 안쪽)은 안쪽 12칸이 좁아 손가락 오조준이 잦다                        |
| 배치      | 모달 상단 **날짜/시간 칩 전환** | 모달 높이가 안 변하고, 팝업이 캘린더를 덮지 않는다                                 |
| 시각 표기 | **항상 24시 고정** (`13:10`)    | 입력 화면은 항상 같은 모양이어야 한다. `uiPrefsStore.timeFormat`과 연동하지 않는다 |

`timeFormat` 설정은 거래 내역 **목록의 표시**에만 계속 쓰인다. 피커는 이 설정을 읽지 않는다.

## 컴포넌트 구조

### `src/lib/utils/timeUtils.ts` (신규)

DOM에 의존하지 않는 순수 함수만 둔다. 기존 vitest 설정(`environment: "node"`,
`include: ["src/**/*.test.ts"]`)에서 그대로 테스트된다.

```ts
type Period = "AM" | "PM";

to24h(hour12: number, period: Period): number      // (12, "AM") -> 0,  (12, "PM") -> 12
from24h(hhmm: string): { hour12: number; minute: number; period: Period }
setHour(hhmm: string, hour12: number, period: Period): string   // "HH:mm"
setMinute(hhmm: string, minute: number): string                 // "HH:mm"
dialPoint(index: number, radius: number): { x: number; y: number }  // index 0 = 12시 방향(위), 시계방향 증가
```

`setHour`/`setMinute`는 입력이 빈 문자열이거나 형식이 깨졌을 때 `00:00`을 기준으로 삼는다.

`dialPoint`의 `index`는 다이얼 칸 번호(0~11)이지 시각 값이 아니다. 각 단계의 매핑은 다음과 같다.

- 시 다이얼: `index 0` = 12시, `index 1` = 1시, … `index 11` = 11시
- 분 다이얼: `index i` = `i * 5`분 (`index 0` = 00분)

### `src/components/ClockDial.tsx` (신규)

```ts
interface ClockDialProps {
  value: string; // "HH:mm" | ""
  onChange: (value: string) => void;
}
```

날짜도 모달도 모르는 자족적 컴포넌트. 내부 상태는 `step: "hour" | "minute"` 하나뿐이다.

구성:

1. **상단 시각** — `13:10` 24시 표기. 현재 단계의 자리는 진하게, 나머지는 흐리게.
   시 자리 / 분 자리를 탭하면 해당 단계로 되돌아간다.
2. **SVG 다이얼** — 12칸. `step === "hour"`면 12·1·2…11, `step === "minute"`면 00·05…55.
   선택된 값에 teal 원형 마커 + 중심에서 뻗는 바늘.
3. **오전/오후 세그먼트 토글** — 두 단계 모두에서 계속 보인다.

동작:

- 시를 탭 → 값 반영 후 `step`이 `"minute"`으로 자동 전환
- 분을 탭 → 값 반영. 단계는 그대로 유지되고 모달도 닫히지 않는다
- 오전/오후 토글 → 현재 시각의 시를 ±12 이동
- `value`가 빈 문자열이면 상단 시각은 `--:--`, 다이얼은 선택 마커와 바늘 없이 렌더.
  토글은 `오전`이 눌린 상태로 보인다

`value`가 빈 상태에서의 첫 입력은 `00:00`을 기준으로 계산한다. 즉 빈 값에서 `3`을 탭하면
`03:00`, 오전/오후 토글을 먼저 누르면 `12:00`이 된다. `setHour`/`setMinute`의 폴백과 같은 규칙이다.

분 선택 후 모달을 자동으로 닫지 않는 이유는 오조준 복구를 쉽게 하기 위해서다.
대신 `view === "time"`인 동안 `완료` 버튼을 teal로 강조해 다음 행동을 가리킨다
(단계와 무관하게 시간 뷰이기만 하면 강조된다).

### `src/components/DateTimePicker.tsx` (수정)

모달 내부에 `view: "date" | "time"` 상태를 추가한다. 캘린더 렌더 로직은 손대지 않는다.

- 모달 최상단에 칩 2개: `[ 8월 4일 (화) ]` `[ 13:10 ]`. 누르면 아래 영역이 캘린더 ↔ 다이얼로 바뀐다
- 시간이 비어 있으면 시간 칩은 `--:--`
- 모달을 열면 항상 `view: "date"`로 시작한다
- 날짜를 선택해도 뷰는 바뀌지 않는다 (날짜만 고치러 오는 경우가 많다)
- 기존 `<input type="time">` 행을 제거한다. `지우기` 버튼은 `시간 지우기`로 이름을 바꿔 하단에 남긴다
- 트리거 버튼의 표시 텍스트(`2026년 8월 4일 (화)  13:10`)는 그대로 둔다

## 기존 동작 변경

`selectDay`에서 `if (!time) onTimeChange('00:00')` 한 줄을 **제거한다**.

현재는 시간을 `지우기`로 비운 뒤 날짜를 다시 누르면 `00:00`이 되살아난다. `지우기`가 있는 이상
"시간 미입력" 상태는 사용자가 의도해서 만든 것이므로 날짜 선택이 이를 되돌리면 안 된다.

이 변경으로 신규 거래 입력에 영향은 없다. `AddTransactionModal`이 이미 `time`을 현재 시각으로
채워서 넘기기 때문에(`AddTransactionModal.tsx:101-107`) 신규 입력 시 `time`이 비는 경로가 없다.

## 데이터 흐름

변경 없음. `time`은 여전히 `HH:mm` 문자열로 `AddTransactionModal`을 거쳐
`transactions.time VARCHAR(5)`에 저장된다. DB 스키마 변경도, 쿼리 변경도 없다.

## 검증

**단위 테스트** — `src/lib/utils/timeUtils.test.ts`

12시간제 ↔ 24시간제 변환의 자정/정오 경계가 핵심이다. 가장 자주 깨지는 지점:

- `to24h(12, "AM") === 0`, `to24h(12, "PM") === 12`
- `from24h("00:30")` → `{ hour12: 12, period: "AM" }`
- `from24h("12:30")` → `{ hour12: 12, period: "PM" }`
- `setHour("13:10", 12, "AM")` → `"00:10"` (분은 보존)
- `setMinute("", 25)` → `"00:25"` (빈 값 폴백)
- `dialPoint(0, r)`가 12시 방향(위쪽)을 가리키는지

**수동 확인** — 컴포넌트 테스트는 현재 셋업(node 환경, `.ts`만 수집)에 없다. 앱을 띄워
거래 추가 → 날짜/시간 칩 전환 → 시·분 선택 → 저장까지 확인하고, 저장된 값이 목록에
맞게 뜨는지 본다. `timeFormat`을 오전·오후로 바꿔도 피커는 24시 표기를 유지하는지 확인한다.
